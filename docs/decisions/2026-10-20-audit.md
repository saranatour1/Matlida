# What the existing code needs: an audit

Asked for mid-run: "also read anything that needs an update, any hiccup,
any bug". Five readers went over the backend, the frontend, the docs, the
tooling and the texting, reminders, calls and auth flows, and a second pass
tried to refute each finding by reading the code again. Nothing here was
changed; each item is the operator's call. Line numbers are from master at
`849ef53`.

## Confirmed bugs

- **High. Talking over a call reply races the still-running turn**
  (`convex/models/threads/calls.ts:175`, `src/components/voice-call.tsx:160`).
  The browser starts listening and can send a second `turn` while the first
  is still streaming. The first reply's line is only inserted when its stream
  ends, so the cut-off mark lands on the wrong line and the transcript ends
  up out of order; nothing aborts the old reply, so it keeps generating,
  voicing and billing, and lands in the chat unheard; and on a call's very
  first turn the client has no `threadId` or `callId` yet, so an
  interruption starts a second chat and a second call record. Fix: have the
  new turn abort the old one (`abortStream` on the agent component), insert
  the reply's line when the stream starts, and refuse or queue a turn until
  the first one has returned its ids.
- **Medium. A superseded text turn still saves its prompt and reply**
  (`convex/models/texts/functions.ts`, `respond` and `answer`). In collapse
  mode a new text cancels the chain, but `isCancelled` is only checked after
  the model has answered, and `generateText` has already saved the prompt
  and the reply to the thread. Two quick texts leave the first one twice in
  the thread with an orphan reply, and pay for two replies. Fix: check
  `isCancelled` before generating and pass an abort signal.
- **Medium. The chat box is cleared even when sending fails**
  (`src/components/prompt-form.tsx:35`). A message starting with a slash
  that isn't a command throws, and the text is gone. Fix: return the prompt
  with the error and use it as the textarea's default value.
- **Medium. The microphone stays on after the mic button unmounts**
  (`src/components/voice-button.tsx:28`). Tap the mic, then a suggestion or
  another assistant: the recording indicator stays lit. Fix: stop the
  recorder and its tracks on unmount.
- **Medium. Template links lose the template for anyone not signed in**
  (`src/routes/_app/route.tsx:30`). The sign-in redirect drops the
  `?template=` search, so a shared link only works for someone already
  signed in. Fix: carry a same-origin redirect through sign-in.
- **Medium. A command picked from the "+" menu dispatches outside a
  transition** (`src/components/prompt-form.tsx:75`). React logs an error on
  every use. Fix: wrap in `React.startTransition`.
- **Low. `connectTelegram` caches a rejected promise**
  (`convex/models/texts/sender.ts:114`). After a failed start with a wrong
  token, later Telegram sends in the same container never retry. Fix: use
  the same guarded form the send path uses.
- **Low. An unknown `?thread=` shows a raw stack trace**
  (`src/components/chat.tsx:58`). Fix: load the thread first and show
  "Chat not found".
- **Low. Navigations that force `?panel=true` cover the chat on phones**
  (`src/components/call-history.tsx:127`). Fix: drop the flag on phones and
  keep the panel's close button in a non-scrolling header.
- **Low. The group-chat picker keeps the text typed to find the action**
  (`src/components/command-menu.tsx:162`). Fix: control the input and clear
  it when picking starts.
- **Low. Agent stream errors log the raw AI SDK error**, which carries the
  whole request body (`convex/models/threads/chat.ts:206`). Fix: wrap the
  model so errors are rethrown without `requestBodyValues`.

## Stale docs

- `README.md` "What's here" and Scripts still describe the auth-only
  starter; `pnpm check` and `pnpm test` aren't listed.
- `README.md:44`: the Photon env vars are needed for Telegram too, not just
  iMessage and WhatsApp.
- `README.md`, `tasks.md`, `progress.md` and a comment in
  `convex/models/calls/functions.ts` say `npx convex …` although the rule
  is pnpm only. The setup guide in this stack uses `pnpm exec`.
- `AGENTS.md:30` says `strictPort` enforces the port, but `--port 3001`
  still starts the dev server; only a taken port is refused.
- `.claude/skills/verify-matlida/SKILL.md` and its feature recipes expect a
  signed-in "home card" at `/` with a Sign out button; sign-in now lands on
  `/p/<id>` with the chat and sidebar.
- `convex/README.md` is Convex boilerplate that tells people to create
  `convex/myFunctions.ts`, which the repo's lint rule refuses.

## Reported but not verified

The verification pass stopped at twenty findings. These were reported by one
reader and not checked by a second:

- High: a superseded text turn keeps generating, so tools such as
  `set_reminder` and `save_plan` can run twice (same root cause as the
  confirmed medium above).
- Medium: answering a call reminder marks it delivered before the call
  exists, and a failed opening is swallowed (`convex/models/threads/calls.ts:246`).
- Medium: text reminders are marked sent when queued; a failed delivery
  leaves no trace (`convex/models/reminders/functions.ts`).
- Medium: `set_reminder` treats an offset-less ISO time as UTC
  (`convex/models/threads/tools.ts:110`).
- Medium: `pnpm start` points at a Nitro `.output` path this build never
  produces (`package.json:11`).
- Medium: `scripts/pr-size.sh` reports 0 lines and exits 0 when the base
  ref doesn't exist.
- Medium: the exact AI SDK overrides in `pnpm-workspace.yaml` pin
  `@ai-sdk/gateway` below what `ai` ships and will downgrade on the next
  `pnpm up`.
- Medium: `pnpm check` never runs the tests.
- Low: the voice call panel stays on "Thinking…" after a failed turn;
  expired link codes still show on Messaging; text reminders go to the most
  recently linked app rather than the chat they came from; `src/router.tsx`
  names `CONVEX_URL` instead of `VITE_CONVEX_URL` in its error; the
  `.prettierignore` `**/api` line keeps `convex/api` out of `pnpm format`;
  `pnpm.onlyBuiltDependencies` in `package.json` is dead config under pnpm
  11+; no `engines` or `packageManager` pin; `tasks.md`'s Open section is
  mostly ticked items; the orb avatars entry in `progress.md` names files
  that no longer exist.

## Refuted

- "`syncProfile` wipes a user's name, email and image when the provider
  omits them": the triggers aren't possible with the providers in use.
- "`transcribeClip` deletes the recording before checking it exists":
  the order is safe in practice.
